Part 5 · The ML procedure

The 7-step procedure of machine learning

A machine learning project is more than training a model: it starts with a well-posed problem and ends with a model that keeps working in service. The process is highly iterative, so expect to loop back and try many ideas before one satisfies you.

Step 1: Problem characterization

Right problems lead to opportunities. Data-driven ML is appropriate only when three requirements hold:

  1. A pattern exists. Without regularities in the data, there is nothing to learn.
  2. The pattern cannot be pinned down mathematically with a tractable model. Pedestrians usually follow a linear motion model that a Kalman filter handles, but jaywalking and other human behavior are too complex to model.
  3. Data is available. The intelligence is in the data: garbage in, garbage out.

Step 2: Data collection

Design of experiments (DOE) plans which combinations of factor levels to run. Both breadth (how many factors) and depth (how many levels) matter. A full factorial design with \(k\) factors at \(L\) levels needs \(L^k\) runs; a regular fractional design \(L^{k-p}\) runs only a fraction of them.

DOE run calculator

Interactive

Real experiments rarely give every factor the same number of levels. A mixed-level full factorial runs every combination, so the run count is the product of the level counts, \(N = L_1 \times L_2 \times \cdots \times L_k\). Two 3-level factors, two 2-level factors and one 4-level factor need \(3 \cdot 3 \cdot 2 \cdot 2 \cdot 4 = 144\) runs.

Mixed-level DOE planner

Interactive
Factors and levels
Up to 7 factors, 2 to 5 levels each.

A pairwise (all-pairs) screening design makes every combination of levels for every pair of factors appear at least once, so all main effects and two-factor combinations are exercised with far fewer runs; higher-order interactions are not covered. Another standard option for mixed levels is an orthogonal array, such as the Taguchi \(L_{18}\) array, which studies one 2-level factor and up to seven 3-level factors in only 18 balanced runs.

Full factorialFractional factorial
ProsEvery combination is covered. Analysis is straightforward because nothing is aliased.Less effort, memory and time. Runs can be added later to remove confounding.
ConsThe cost grows quickly with the number of factors.Higher-order interactions are hard to analyze. Confounding (aliasing) can mask factor and interaction effects.
A two-level fractional design \(2^{k-p}\) builds the extra factors from products of the base factors, for example \(D = ABC\). The price is aliasing: you cannot tell the effect of \(D\) apart from the \(ABC\) interaction. Three-level fractional designs \(3^{k-p}\) follow the same idea.

Step 6: Evaluation and optimization

Nickname: evaluate the confession. Compare against a baseline or target values, not against perfection. Key questions are the probability of detection (PD), the probability of false alarm (PFA), and how much confidence you can place in them. The tools are generalization checks, the confusion matrix, ROC and DET curves, error analysis and robustness tests.

A model that is too simple has high bias and low variance: it underfits. A model that is too complex has low bias and high variance: it overfits. The best balance gives the smallest testing error with an acceptable training error, the same trade-off as the curve fitting playground in Part 3.

FP is a Type I error (false alarm). FN is a Type II error (miss).

A receiver operating characteristic (ROC) curve plots the true-positive rate (sensitivity, recall) against the false-positive rate (\(1 -\) specificity) as the decision threshold varies. The area under the curve (AUC) compares classifiers: close to 1 is excellent, while 0.5, the diagonal, carries no information. A detection error trade-off (DET) curve plots the two error rates (miss versus false alarm) on normal-deviate axes, where the curves become nearly straight lines.

Robustness. A model should not be overly sensitive to small perturbations. The one-pixel attack showed that changing a single pixel can flip the prediction of a deep network (J. Su, D. Vargas and K. Sakurai, 2017), so robustness tests with perturbed inputs belong in every evaluation plan.

1. Independence

Knowing one reading tells you nothing about another, so \(p(x_1, \dots, x_n) = \prod_i p(x_i)\). Readings taken one second apart from the same pump break this: a bearing that vibrates strongly now will almost certainly still vibrate strongly a second later.

2. Identical distribution

Every reading follows the same distribution \(f(x; \mu, \sigma^2)\), with the same \(\mu\) and \(\sigma^2\) in training and in service. A model trained on new pumps in a cool plant, then deployed on aged pumps in a hot plant, breaks this.

Now move the idea to industry. A predictive maintenance model watches pump bearings: each observation is one vibration reading (RMS velocity in mm/s), and the model raises an alarm when a reading looks abnormal. Consecutive readings from one pump play the role of the video frames, and a new site or an aging fleet plays the role of the night-vision camera.

If readings are not independent

Split the data by time or by machine, never at random, or near-identical neighbors land in both the training and test sets and inflate the test score. Summarize windows into features (RMS, kurtosis, trend), or use a sequence model that expects dependence.

If the distribution is not identical

Monitor drift by comparing live statistics with the training data. Recalibrate sensors, collect data from the new site or older machines, and retrain or adapt the model.

IID = independence + identical distribution. When either part fails, the accuracy you measured during development no longer predicts the accuracy you will get in the field.

IID also implies that behavior does not change over time. In many applications that assumption is simply false, so a deployed model must cope with:

Sensor imperfection

Faults, aging and miscalibration.

Nonstationarity

The data-generating process itself changes.

Drift over time

Gradual concept drift from wear or seasons.

Evolving data

New classes and new operating regimes.

Concept drift: static versus adaptive model

Interactive

Both are nearest-centroid classifiers. The static model is trained once on the first 200 samples. The adaptive model (passive approach) retrains every 25 samples on the most recent window of labeled samples.

Two families of adaptation (G. Ditzler, M. Roveri, C. Alippi and R. Polikar, IEEE Computational Intelligence Magazine, 2015): the active approach uses a change detector and adapts only when drift is detected; the passive approach updates the model continuously as new data arrive. Related ideas include domain adaptation, transfer learning and continual learning.

# Learning as optimization: choose f from a model class to minimize the sample loss (curve fitting)
import numpy as np

rng = np.random.default_rng(0)
truth = lambda x: np.sin(2 * np.pi * x)
x_test = np.linspace(0, 1, 200); y_test = truth(x_test)


def sample(n):
    x = rng.random(n)
    return x, truth(x) + 0.25 * rng.standard_normal(n)


def fit(x, y, degree):
    """Least squares: the f in the class of degree-d polynomials that minimizes the mean squared error."""
    V = np.vander(x, degree + 1)
    w, *_ = np.linalg.lstsq(V, y, rcond=None)
    return lambda t: np.vander(t, degree + 1) @ w


mse = lambda f, x, y: np.mean((f(x) - y) ** 2)
x, y = sample(15)
print("15 training points")
print(" degree  train MSE  test MSE")
for d in (1, 3, 5, 9, 12):
    f = fit(x, y, d)
    print(f"  {d:2d}     {mse(f, x, y):.3f}     {mse(f, x_test, y_test):.3f}")      # high degrees overfit

print("degree 9 with more data (the unreasonable effectiveness of data)")
for n in (15, 50, 200, 1000):
    xs, ys = sample(n)
    print(f"  n = {n:4d}: test MSE {mse(fit(xs, ys, 9), x_test, y_test):.3f}")

# The same idea with gradient descent: a line y = a x + b fitted by minimizing the sample score S(f)
x, y = sample(50)
a = b = 0.0
for step in range(2000):
    err = a * x + b - y
    a -= 0.5 * np.mean(err * x); b -= 0.5 * np.mean(err)
print(f"gradient descent line: y = {a:.2f} x + {b:.2f}, MSE {np.mean((a * x + b - y) ** 2):.3f}")
# One dataset, three learning paradigms: supervised, unsupervised and semi-supervised (Figure 11.2)
import numpy as np

rng = np.random.default_rng(1)
X = np.vstack([rng.normal([-1.5, 0], 0.7, (100, 2)), rng.normal([1.5, 0.5], 0.7, (100, 2))])
y = np.repeat([0, 1], 100)

# Supervised: logistic regression learns from all the labels
w, b = np.zeros(2), 0.0
for _ in range(2000):
    p = 1 / (1 + np.exp(-(X @ w + b)))
    w -= 0.1 * X.T @ (p - y) / len(y); b -= 0.1 * np.mean(p - y)
sup = (X @ w + b > 0).astype(int)
print(f"supervised (all 200 labels):      accuracy {np.mean(sup == y):.1%}")

# Unsupervised: k-means sees no labels at all; it can only group the points
C = X[rng.choice(len(X), 2, replace=False)]
for _ in range(50):
    lab = ((X[:, None] - C) ** 2).sum(-1).argmin(1)
    C = np.array([X[lab == j].mean(0) for j in range(2)])
acc = max(np.mean(lab == y), np.mean(lab != y))           # cluster ids are arbitrary
print(f"unsupervised (no labels):         agreement with the classes {acc:.1%}")

# Semi-supervised: 4 labels, then self-training with pseudo-labels for the rest
known = np.array([0, 1, 100, 101])
labels = np.full(len(y), -1); labels[known] = y[known]
for _ in range(10):
    mask = labels >= 0
    cent = np.array([X[mask & (labels == k)].mean(0) for k in (0, 1)])
    d = ((X[:, None] - cent) ** 2).sum(-1)
    conf = np.abs(d[:, 0] - d[:, 1])
    unl = np.flatnonzero(~mask)
    if not len(unl):
        break
    pick = unl[np.argsort(-conf[unl])[:20]]             # pseudo-label the 20 most confident points
    labels[pick] = d[pick].argmin(1)
semi = ((X[:, None] - np.array([X[labels == k].mean(0) for k in (0, 1)])) ** 2).sum(-1).argmin(1)
print(f"semi-supervised (4 labels):       accuracy {np.mean(semi == y):.1%}")
# ML for optimization, "learning to configure algorithms" (Figure 11.14): a bandit picks the step size of a search
import math
import random

def rastrigin(x):
    return 10 * len(x) + sum(v * v - 10 * math.cos(2 * math.pi * v) for v in x)

STEPS = [0.02, 0.1, 0.5, 2.0]


def search(choose, rng, iters=3000, dim=5):
    """A (1+1) random search: perturb the current point with Gaussian noise of a chosen size, keep it if better."""
    x = [rng.uniform(-5.12, 5.12) for _ in range(dim)]; fx = rastrigin(x)
    n, gain = [0] * len(STEPS), [0.0] * len(STEPS)
    for t in range(iters):
        k = choose(t, n, gain, rng)
        y = [min(5.12, max(-5.12, v + rng.gauss(0, STEPS[k]))) for v in x]
        fy = rastrigin(y)
        reward = max(0.0, fx - fy)                       # reward = improvement
        n[k] += 1; gain[k] += reward
        if fy < fx:
            x, fx = y, fy
    return fx, n


def ucb(t, n, gain, rng, c=0.5):
    for k in range(len(STEPS)):
        if n[k] == 0:
            return k
    return max(range(len(STEPS)), key=lambda k: gain[k] / n[k] + c * math.sqrt(math.log(t + 1) / n[k]))


rng = random.Random(0)
fixed = []
for k, s in enumerate(STEPS):
    res = [search(lambda t, n, g, r, k=k: k, rng)[0] for _ in range(20)]
    fixed.append(sum(res) / 20)
    print(f"fixed step {s:4.2f}: mean best f = {fixed[-1]:6.2f}")
print(f"a fixed step picked blindly averages {sum(fixed) / len(fixed):6.2f}")
runs = [search(ucb, rng) for _ in range(20)]
print(f"UCB-chosen step: mean best f = {sum(r[0] for r in runs) / 20:6.2f}; pulls per step size in one run {runs[0][1]}")
# Combinatorial optimization: the TSP search space, then construction (L2C) vs. improvement (L2I) heuristics
import math
import random

for n in (5, 10, 14, 20):
    print(f"{n:2d} cities: (n - 1)! = {math.factorial(n - 1):.3e} tours, (n - 1)!/2 = {math.factorial(n - 1) // 2:.3e} undirected")
# 14 cities: (14 - 1)! = 13! = 6,227,020,800, not 622,702,080

rng = random.Random(5)
P = [(rng.random(), rng.random()) for _ in range(60)]
L = lambda t: sum(math.dist(P[t[i]], P[t[i - 1]]) for i in range(len(t)))


def nearest_neighbor(start=0):
    """Construction: build a tour by always visiting the closest unvisited city."""
    tour, left = [start], set(range(len(P))) - {start}
    while left:
        nxt = min(left, key=lambda j: math.dist(P[tour[-1]], P[j]))
        tour.append(nxt); left.remove(nxt)
    return tour


def two_opt(tour):
    """Improvement: reverse a segment whenever that shortens the tour, until no reversal helps."""
    improved = True
    while improved:
        improved = False
        for i in range(1, len(tour) - 1):
            for j in range(i + 1, len(tour)):
                a, b, c, d = P[tour[i - 1]], P[tour[i]], P[tour[j]], P[tour[(j + 1) % len(tour)]]
                if math.dist(a, c) + math.dist(b, d) < math.dist(a, b) + math.dist(c, d) - 1e-12:
                    tour[i:j + 1] = reversed(tour[i:j + 1]); improved = True
    return tour


t = nearest_neighbor()
print(f"nearest neighbor (construct): {L(t):.3f}")
print(f"after 2-opt (improve):        {L(two_opt(t)):.3f}")
rand = list(range(60)); rng.shuffle(rand)
print(f"random tour {L(rand):.3f} -> 2-opt {L(two_opt(rand)):.3f}")
